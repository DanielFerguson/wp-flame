# Support scope

Status: public-RC operating policy; commercial response targets remain subject to the paid design-partner gate.

## Supported

- Installation, activation, capture health, and removal of a supported WP Flame release.
- Reproduction of a WP Flame defect on the documented WordPress/PHP/database matrix.
- Help interpreting capability, incompleteness, storage, migration, and persistence states.
- Clarification of the evidence shown in a trace or compatible cohort comparison.
- Acknowledgement and triage of reproducible accessibility or compatibility defects.

## Not included in software support

- Guaranteed diagnosis or repair of third-party site code, hosting, databases, networks, or external services.
- General WordPress development, performance implementation, incident response, or emergency site restoration.
- Browser performance, Core Web Vitals, page-cache/CDN hits, arbitrary PHP functions, or infrastructure behavior outside WP Flame's documented boundary.
- Review of raw sensitive trace data unless a separately scoped engagement and explicit authorization exist.

Expert performance reviews, if offered, are separately priced and scoped. Buying software support does not authorize WP Flame or its operator to access a customer's site or trace data.

## Before opening a request

1. Record the WP Flame version and affected request population.
2. Export the redacted default bundle with `wp flame support-bundle`.
3. Describe expected versus actual behavior and whether Safe mode changes it.
4. Include screenshots or redacted exports only after reviewing them.
5. Never send credentials, cookies, license keys, raw SQL literals, personal data, or an unreviewed database dump.

The public support channel and paid response targets must be inserted on the commercial website before checkout opens. Until beta capacity is measured, no guaranteed SLA is promised.
